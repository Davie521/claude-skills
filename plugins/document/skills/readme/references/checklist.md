# README 检查清单

审查时逐项对照，报告里只列不合格的项（格式见 SKILL.md「汇报」）。每项写「README:行」；问题出在 README 之外的，写「README:行 ↔ 文件:行」，并标明是实测还是读代码推断。写作时用它在交付前自查。

## 第一屏（不滚动能看到的部分）

- [ ] 标题下第一句话说清它**做什么**，不用「强大的 / 轻量的 / 现代化的」。
- [ ] 这句话和 GitHub 仓库的 About 描述说的是同一件事。
- [ ] 有真实画面（截图、录屏、真实输出），不是 mockup，也不是 AI 生成图；`alt` 是一句完整描述。
- [ ] 非官方、已停更、协议有限制、依赖未公开接口：在第一屏或紧跟着的位置说了。
- [ ] 协议和 README 宣传的用法不矛盾（例：标榜「自托管、随便改」却用了禁止修改的 CC BY-NC-ND）；矛盾的话提醒用户，不替他改协议。
- [ ] 第一屏里没有目录树、架构图、贡献指南。

## 事实

- [ ] 每条命令都实测过，或者明确标了「未实测」并告诉了用户。
- [ ] 包管理器、命令行参数、环境变量名、默认值、阈值都对过代码。
- [ ] 最低版本和 CI 矩阵里实际跑的版本一致。
- [ ] 环境变量表和代码、`docker-compose.yml`、`.env.example` 三处一致：必填项没有漏，「可选」的确实可选。
- [ ] 运行时依赖的外部服务（OAuth、汇率/天气等第三方 API、构建时抓取）写了，并说了它们挂掉时会怎样。
- [ ] 没有写还没实现的功能，也没写「coming soon」式的 Roadmap。
- [ ] 安装时改过全局状态（偏好设置、launchd、钩子、PATH）的，卸载一节逐项都有对应的撤销。
- [ ] 反向审计：文档里提到的文件都还在；重要的受控文件（CI、安装脚本、配置样例）文档里提到了。
- [ ] 相对链接、锚点、图片都能打开（锚点用 `gh api /markdown` 渲染后核对）。

## 结构

- [ ] 给维护者看的东西（发版流程、目录树、CI 密钥、调试指南）不在 README 里，已经搬去 `CONTRIBUTING.md` 或 `docs/` 并留了链接。
- [ ] 只回答：是什么、跟别的有什么不同、怎么装、有什么限制、细节去哪看。其余已搬进 `docs/`。
- [ ] 一个事实只出现一次。
- [ ] 安装是一步（一条命令或一段给 agent 的提示词），而且只写了读者还剩下要做的事。
- [ ] 第一次试用可能出现的「怎么没反应」已经预先说了，并给了验证方法。
- [ ] 没有空占位的小节（空的 Support、Roadmap、FAQ、Authors）。
- [ ] 超过约 150 行正文（不算代码块）的，已经考虑搬走或者加了目录。
- [ ] 作者原有的装饰（徽章、logo、star 曲线）没有在作者不同意的情况下删掉。
- [ ] 双语：两份的小节、命令、数字逐项对齐，中文是重写而不是逐句翻译。

## AI 腔

下面这些不是要勾的项，是出现了就要改的写法。


- emoji 小标题（🚀 Quick Start、✨ Features、📦 Installation）。
- 吹嘘词：强大、轻量、优雅、无缝、一站式、开箱即用、赋能、极致；blazing fast、seamless、robust、powerful、leverage、cutting-edge、effortless。
- 三连排比、「三道防线」式编号口号、每段一句金句。
- 满屏加粗：一节超过两处。
- 每节一张表，包括只有一个维度的信息。
- 没人问过的 FAQ。
- 「总而言之」「值得一提的是」「In conclusion」「Moreover」这类过渡。
- 用散文把代码复述一遍，而不是链到代码。
- 模棱两可的说法：「可能」「通常」「应该可以」，而事实其实可以查清。
- 一墙徽章，或者「made with ❤️」「PRs welcome」这类没有信息量的徽章。
- Features 里的粗体是名词（「Smart Thresholds」），不是结论（「Only when it is worth it.」）。

## 隐私（私人仓库也要查）

- [ ] 没有真实手机号、邮箱（作者公开的联系邮箱除外）、token、密钥、UDID、1Password 条目 ID。
- [ ] 没有局域网 IP、Tailscale 100.x 地址、ssh 别名后面的真实主机、家庭住址、Wi-Fi 名。
- [ ] 截图里也没有以上内容。
- [ ] 私人仓库里，敏感值换成了占位符，并写明真实值放在哪个不进仓库的本地文件里。
