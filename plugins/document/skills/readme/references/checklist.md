# README 检查清单

审查时逐项对照，报告里只列不合格的项，并引用编号（格式见 SKILL.md「汇报」）。AI 腔的规则在 ai-tone.md，用 AI-1 到 AI-10 引用。每项写「README:行」；问题出在 README 之外的，写「README:行 ↔ 文件:行」，并标明是实测还是读代码推断。写作时用它在交付前自查。

## 第一屏（不滚动能看到的部分，大约是标题往下 30 行，或第一个安装小节之前）

- **F1** 标题下第一句话说清它**做什么**，不用「强大的 / 轻量的 / 现代化的」。
- **F2** 这句话和 GitHub 仓库的 About 描述说的是同一件事。
- **F3** 有真实画面（截图、录屏、真实输出），不是 mockup，也不是 AI 生成图；`alt` 是一句完整描述。
- **F4** 非官方、已停更、协议有限制、依赖未公开接口：在第一屏或紧跟着的位置说了。
- **F5** 协议和 README 宣传的用法不矛盾（例：标榜「自托管、随便改」却用了禁止修改的 CC BY-NC-ND）；矛盾的话提醒用户，不替他改协议。
- **F6** 第一屏里没有目录树、架构图、贡献指南。

## 事实

- **T1** 每条命令都实测过，或者明确标了「未实测」并告诉了用户。
- **T2** 包管理器、命令行参数、环境变量名、默认值、阈值都对过代码。
- **T3** 最低版本和 CI 矩阵里实际跑的版本一致。
- **T4** 环境变量表和代码、`docker-compose.yml`、`.env.example` 三处一致：必填项没有漏，「可选」的确实可选。
- **T5** 运行时依赖的外部服务（OAuth、汇率/天气等第三方 API、构建时抓取）写了，并说了它们挂掉时会怎样。
- **T6** 没有写还没实现的功能，也没写「coming soon」式的 Roadmap。
- **T7** 安装时改过全局状态（偏好设置、launchd、钩子、PATH）的，卸载一节逐项都有对应的撤销。
- **T8** 反向审计：文档里提到的文件都还在；重要的受控文件（CI、安装脚本、配置样例）文档里提到了。
- **T9** 相对链接、锚点、图片都能打开（锚点用 `gh api /markdown` 渲染后核对）。
- **T10** 外部链接能打开，尤其是在线 Demo、文档站和 GitHub About 里的主页链接。Demo 挂了是伤害最大的一类问题：读者点开 404 就走了。

## 结构

- **S1** 给维护者和 agent 看的东西（发版流程、目录树、CI 密钥、调试指南、`CLAUDE.md` / `AGENTS.md`）不在 README 里，也没有被当成「架构文档」推荐给读者，已经搬去 `CONTRIBUTING.md` 或 `docs/` 并留了链接。
- **S2** 读者和用户内容的顺序符合 SKILL.md 第 1 步那张表里这类仓库的漏斗顺序。
- **S3** 一个事实只出现一次。
- **S4** 安装是一步（一条命令或一段给 agent 的提示词），而且只写了读者还剩下要做的事。
- **S5** 第一次试用可能出现的「怎么没反应」已经预先说了，并给了验证方法。
- **S6** 没有空占位的小节（空的 Support、Roadmap、FAQ、Authors）。
- **S7** 有 `docs/` 或文档站的，README 没有重复细节；没有的，长 README 用问题当小标题，超过约 200 行有目录。
- **S8** 第一屏或第一节给出了第一条命令、第一句话或最小可运行例子，以及之后会发生什么。
- **S9** 产出是文件的，仓库里有一份样例并链了过去。
- **S10** 写了证明过什么；样本小的照实说，没测过的标「还没证明」。
- **S11** 依赖写了版本，附确认命令和预期输出；agent skill 写明了要装哪个目录。
- **S12** 作者原有的装饰（徽章、logo、star 曲线）没有在作者不同意的情况下删掉。
- **S13** 双语：两份的小节、命令、数字逐项对齐，中文是重写而不是逐句翻译。

## 隐私（私人仓库也要查）

- **P1** 没有真实手机号、邮箱（作者公开的联系邮箱除外）、token、密钥、UDID、1Password 条目 ID。
- **P2** 没有局域网 IP、Tailscale 100.x 地址、ssh 别名后面的真实主机、家庭住址、Wi-Fi 名。
- **P3** 截图里也没有以上内容。
- **P4** 私人仓库里，敏感值换成了占位符，并写明真实值放在哪个不进仓库的本地文件里。
